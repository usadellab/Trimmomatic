Version 0.42: Feature: POLYX trimmer - trims homopolymer runs from the 3' end, drops the read if it is entirely poly-X
              Feature: LOWCOMPLEXITY trimmer - drops reads below a minimum Shannon entropy
              Feature: MAXAMBIG trimmer - drops reads whose fraction of N bases exceeds a maximum
              Feature: UMIEXTRACT trimmer - extracts a UMI from the 5' end into the read name; refuses if applied to both mates in symmetric PE mode, since that would desync mate names
              Feature: UMISPLIT trimmer - extracts a cell barcode and UMI (two separate lengths) from the 5' end into the read name as bare sequences
              Feature: UMIDROPLETCORRECT trimmer - whitelist-corrects a cell barcode (exact match, or 1-mismatch) against a known-good list, then extracts the corrected barcode and raw UMI into the read name as bare sequences, same convention as UMISPLIT; combines correction and extraction in one step for droplet single-cell platforms (10x Genomics and similar)
              Feature: UMIRHAPSODYCORRECT trimmer - whitelist-corrects BD Rhapsody's combinatorial cell label (CLS1/CLS2/CLS3) and extracts it plus the raw UMI into the read name as bare sequences, same convention as UMISPLIT/UMIDROPLETCORRECT; beadVersion argument selects V1 (default) or ENHANCEDV2 (experimental, not validated against real data)
              Feature: per-mate name tags (UMIEXTRACT, UMISPLIT, UMIDROPLETCORRECT, UMIRHAPSODYCORRECT) are mirrored onto the other mate's name too, since the tagged mate is usually discarded before alignment and only the other mate's name survives into a BAM's QNAME for anything downstream to read the tag back out of
              Feature: LONGREADTRIM trimmer - unified long-read adapter trimmer replacing LONGREADCLIP+LONGREADSPLIT; indel-aware edit-distance matching with a platform hint (ONT/CLR/HIFI) controlling chimera splitting
              Feature: -longread flag (SE and PE) - skips the phred pre-read and assumes Phred+33, for ONT/PacBio input
              Feature: -technicalread <1|2> flag (PE only) - one mate (cell barcode/UMI) passes through untouched while all trimmers run on the other; if the biological mate is dropped both are discarded, the technical mate never appears in the unpaired output
              Feature: -pe1steps/-pe2steps flags (PE only) - run an independent step list per mate instead of one shared list; either mate's steps dropping a read drops the whole pair
              Feature: -interleaved flag (PE only) - a single file of alternating R1/R2 reads is split into two virtual streams
              Feature: Bundled long-read adapter FASTA files for common ONT and PacBio kits
              Fix: MaximumInformationTrimmer crashed on reads longer than 1000bp
              Fix: various file-handle and background-thread leaks on error paths (parser open failures, exceptions mid-trim) now clean up correctly
              Fix: LongReadTrimmer missed some adapters on HIFI reads near the 3' terminus
              Fix: stats summary could undercount at high thread counts (SE and PE) due to a race between the main thread and the background stats-merging thread; the trimmed FASTQ output itself was always correct, only the printed/written summary numbers were affected
              Removed: BarcodeSplitter - unreachable from the command line, wrong shape for whitelist-scale lookups
              Performance: LongReadTrimmer adapter matching much faster via bit-parallel edit distance and k-mer pre-filtering (~22% CPU, ~28% peak RSS on a 3.5M-read ONT benchmark)
              Performance: Parser block size capped by both record count and byte volume, preventing heap exhaustion on long-read inputs
              Build: -version now appends the git commit hash and a -dirty suffix when uncommitted changes are present
              Rename: BARCODECORRECT to UMIDROPLETCORRECT, BDRHAPSODYCORRECT to UMIRHAPSODYCORRECT, so every UMI step name starts with UMI
